# Known limitations

These are behavior gaps, not permissions to disable tests. Keep focused regression cases enabled and distinguish deterministic local evidence from live-provider acceptance.

- **Slack preview acceptance:** the originating sandbox was deployed with both preview switches and mappings disabled; [historical deployment checks](phase-6-rollout.md#infrastructure-and-verification) passed, but native Slack-client acceptance remains outstanding. The recorder models same-ID task titles as replacements, but real rendering and final-title cleanup remain unverified. Keep P1 disabled if replacement is ambiguous; never append speculative Markdown/details/output as fallback.
- **Slack excerpt scope:** only an already opened Slack-origin card receives a rolling provisional title, at most forty writes/two-second cadence in 120 seconds. Missing starts/deltas, queue delays, AppSync errors, rate limits or ambiguous appends can lose the whole preview. After human input the card stays closed; resumed canonical replies do not gain a new preview card. There is no editable extra message or token-perfect transcript.
- **Slack lease/transport limits:** a network acknowledgment can be lost after an optional title was accepted; P1 stops without retrying it. An eight-second DB claim bounds interference with P0, whose ordinary projection retry remains authoritative. Slack can auto-finalize a stream after ten minutes; P1 stops before that limit. P0's existing behavior for an already auto-finalized card is unchanged and cannot guarantee its draft title can still be replaced. No distributed lease can guarantee ordering against an arbitrarily delayed external side effect; HTTP deadlines and terminal fencing bound ordinary races, not exactly-once Slack delivery.

- **Uncertain CMA sends/confirmations:** provider acceptance and DSQL commit are not atomic. Without canonical evidence, uncertain attempts stay held rather than resending. Use the [operator procedure](operations.md#recovery); never infer non-acceptance from missing Slack output. Controller PostgreSQL tests cover ambiguous send and confirmation recovery.
- **Pinned A2A iterator closure:** the official client may finish after an agent Message before terminal status. Closure is a transport event; recover with canonical `GetTask`, deduplicate stable message IDs, and subscribe again when needed. A2A integration and Web Function tests exercise this path.
- **Partial policy boundary:** only CMA calls paused for approval reach OpenAPPA. Tools configured `always_allow`, tool results and full-session information flow are outside mediation. Only one native HITL authority/offer is supported; non-HITL/multiple remedies, sanitizers and stateful policies fail closed. No whole-transcript enforcement is claimed. Argument selectors match strings, not parsed email addresses, so a comma-joined recipient inside one array element can match an internal pattern; tools must validate their own argument formats.
- **Intermittent Web clarification UI:** the panel may fail to appear or remain stale after Stop while canonical A2A is correctly `INPUT_REQUIRED` and AG-UI emitted an interrupt. Enabled semantic browser tests may pass in isolation; that does not establish a fix. Phase 4 review reconciliation does not claim to resolve every clarification race.
- **Webhook/lease timing:** a terminal webhook arriving while a scheduler lease is busy may wait for SQS retry or the 30-second reconciler (historically about 34 seconds). This is durable recovery, with remaining user-visible latency.
- **External Slack effects:** an accepted write with a lost acknowledgment can remain ambiguous. Receipts and leases prevent normal duplicate/reordered projection but cannot guarantee exactly-once Slack API effects. Missing installed scopes require diagnosis/reinstallation. Local recorder tests cannot prove native Slack rendering or clicks.
- **Native Slack-client acceptance:** the 2026-10-31 sandbox run verified genuine Slack delivery, native human review, Web reload/Allow, signed Slack Deny/duplicates, and pending-review Stop against real CMA. Signed interactions and API-visible blocks do not prove native Slack button clicks or client rendering. See [acceptance evidence](testing.md#optional-live-evidence).

- **Preview delivery:** previews default to disabled. Authorized live fanout passed for two viewers, but two other live turns produced no previews while P0 completed correctly. CMA streams only future events; creating a first session with initial events is unchanged, so earliest tokens or the entire first response can be missed. A 120-second observer may miss later tokens in long generations. No replay, reliable end marker or exactly-once preview delivery is assumed. Missing/truncated/out-of-order previews are disposable; canonical A2A history replaces them.
- **Cloud acceptance:** historical acceptance in the originating sandbox verified standalone IAM rejection, cookie authentication through CloudFront, private A2A history and DSQL access through the connector, and two real IAM AppSync subscribers. Live CMA preview fanout and native review Allow/Deny/Stop also passed. The old Python Web resources were retired and a retained Web revision rollback was exercised; see [the deployment evidence](phase-5-rollout.md). Local fakes alone do not establish those contracts. That Web rollout did not perform schema migration, credential synchronization or CMA definition changes; upgrading from the earlier public release requires the separate preparation in [upgrading](upgrading.md).
- **Terraform Web revision updates:** provider 6.62.0 can report an inconsistent final CloudFront origin-set plan when SAM outputs become unknown during a revision update. Review/apply the saved Web revision plan separately, then run a full plan. The observed failed apply had already updated the revision; CloudFront remained unchanged. Do not blindly retry a stale plan.
- **HTTP lifetime and buffering:** the gateway ends streams after 840 seconds, below AWS's 900-second maximum. Slow consumers lose their stream after five seconds of blocked writes. Clients must recover from canonical history/resume; a transport deadline is never Task completion or cancellation.
- **Network availability and cost:** both connector AZs use one existing NAT and the existing private execute-api endpoint. The second subnet does not establish multi-AZ production HA. Preview operations, observer runtime, concurrent Web requests and NAT egress add cost.
- **Dependency audit:** the 2026-11-01 public-migration `npm audit --json` reports 24 vulnerable package entries (one critical, ten high, thirteen moderate) across the existing browser/tooling and transitive AG-UI trees, including Next and Zod. New server dependencies are pinned, but AG-UI's transitive Zod advisory remains. Browser versions were preserved for this transport migration. Server request bodies are capped at 1 MiB. The critical entry is Next.js; high entries include the AG-UI/Zod chain and build tooling. npm reports no automatic fix for the AG-UI/Zod chain. Dependency remediation remains unresolved; passing local checks does not certify those dependencies secure.

The old Python synchronous SSE adapter and shared-thread-pool bridge were deleted. P0 never reads CMA SSE. The separate Node observer has abort/deadline tests and no shared controller executor, so it cannot exhaust controller SSE workers. Isolation tests establish that boundary; separate live fanout evidence is recorded in the Phase 5 report.
